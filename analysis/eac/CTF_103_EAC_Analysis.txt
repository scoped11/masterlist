2.3 Import Table (Static)
  Only TWO static imports — everything else resolved dynamically at runtime:

  FLTMGR.SYS:
    - FltRegisterFilter  → EAC registers as a MiniFilter driver

  This extreme minimalism means EAC uses MmGetSystemRoutineAddress or manual
  PE parsing to find all kernel APIs at runtime. This defeats static import
  analysis and makes IDA cross-references incomplete without runtime tracing.


PART 3: DETECTION MECHANISMS IDENTIFIED
================================================================================

3.1 Driver Blocklist (CONFIRMED BY LOGS)
  EAC maintains a blocklist of known vulnerable drivers. When a blocklisted
  driver is loaded, EAC refuses to start the game (error code 206).

  CONFIRMED BLOCKED:
    - NalDrvIntel.sys  (Intel NAL driver — our old BYOVD)
    - WdBroker.sys     (Windows Defender Broker — previous BYOVD)

  NOT BLOCKED (game launched successfully with these loaded):
    - SIVX64.sys        (SIV system info driver)
    - ThrottleStop.sys  (CPU throttle control)
    - TRIXX.sys         (Sapphire GPU utility — CURRENT BYOVD)

  Evidence from launcher logs:
    16:03 → "Please unload NalDrvIntel.sys before starting the game" (206)
    16:25 → "Please unload WdBroker.sys before starting the game" (206)
    21:09 → "Easy Anti-Cheat successfully loaded in-game" (301) ← after switch

  The blocklist is likely downloaded from the EAC CDN:
    https://modules-cdn.eac-prod.on.epicgames.com/modules/<ProductID>/<DeploymentID>/win64

3.2 MiniFilter (Filesystem Monitoring)
  EAC registers a MiniFilter via FltRegisterFilter. This intercepts:
    - File creation/opening (IRP_MJ_CREATE)
    - File reads/writes (IRP_MJ_READ/WRITE)
    - Directory queries

  Likely monitors:
    - Game executable integrity (r5apex_dx12.exe)
    - DLL loads from suspicious paths
    - Cheat configuration files
    - Memory-mapped file modifications

3.3 Certificate / Signature Verification
  Unicode strings reveal WinTrust-based driver verification:
    - WINTRUST_ACTION_GENERIC_VERIFY_V2 (GUID: 00AAC56B-CD44-11D0-8CC2-...)
    - DRIVER_ACTION_VERIFY (GUID: F750E6C3-38EE-11D1-85E5-...)
    - Reads: SOFTWARE\Microsoft\SystemCertificates\%s\Certificates\
    - Policy chain: DriverInitializePolicy → DriverFinalPolicy → DriverCleanupPolicy

  EAC verifies Authenticode signatures of loaded kernel drivers. Drivers that:
    a) Are revoked (certificate on CRL)
    b) Are on the vulnerable driver blocklist
    c) Have expired or invalid signatures
  ...will trigger detection.

  OUR TRIXX.sys: DigiCert EV signed, valid certificate, NOT on blocklist = PASSES

3.4 Kernel Callbacks (Inferred from our counter-measures)
  Based on our BetestDriver.c counter-measures, EAC registers:
    - PsSetCreateProcessNotifyRoutine — monitors process creation
    - PsSetCreateThreadNotifyRoutine — monitors thread creation
    - PsSetLoadImageNotifyRoutine — monitors DLL/driver loading
    - ObRegisterCallbacks — monitors handle operations (open process/thread)
    - CmRegisterCallback — monitors registry access
    - Possible: PsSetCreateProcessNotifyRoutineEx2 (extended version)

3.5 Memory Scanning
  EAC's user-mode module (easyanticheat_x64.eac) performs:
    - Signature scanning of game memory for known cheat patterns
    - Stack walking to detect injected code
    - Module enumeration (NtQueryVirtualMemory/VirtualQuery)
    - Thread enumeration for suspicious threads
    - Handle table auditing
    - Working set analysis (NtQueryInformationProcess)

3.6 Anti-Dump / Self-Protection
  - User-mode module (.eac) is fully encrypted on disk (entropy 7.998)
  - Kernel driver uses code virtualization (36MB VM-protected section)
  - Only 2 static imports — dynamic resolution of all APIs
  - PDB path is generic ("Core.pdb") — minimal debug symbols
  - Anti-debug checks via various NtQuery* calls
  - Timing checks to detect single-stepping / breakpoints

3.7 ETW / Telemetry
  EAC likely uses ETW (Event Tracing for Windows) for reporting:
    - Our driver has ETW patching to suppress AC telemetry
    - EtwRegister trampoline hooks referenced in BetestDriver.c
    - Reports sent to Epic/EAC backend for server-side analysis

5.2 SAFE APPROACHES FOR EXTERNAL CHEATS
  a) Use non-blocklisted BYOVD driver (TRIXX.sys — confirmed safe)
  b) Read game memory via physical memory (BYOVD), NOT via handles
  c) Never call OpenProcess/ReadProcessMemory on the game
  d) Clean up all service registry keys after BYOVD use (our mapper does this)
  e) Strip OB callbacks before opening any game handles
  f) External overlay via DWM/DirectX — never inject into game process
  g) Read-only approach: only read offsets, never write game memory
  h) Use DKOM to hide BYOVD driver from PsLoadedModuleList
  i) Timestamp randomization to defeat timing-based detection
